Версия основана на **Photo(2).ipynb**. Научные выводы перенесены из текущего ноутбука; оригинальный полный вывод сохранён без перефразирования. Исходный Colab: https://colab.research.google.com/drive/1TIykhDkBmIEwg3NVIK4BqL7pTjnSKaP7?usp=sharing

## Что увидит преподаватель

- `https://kristina344.github.io/ColorLab/` — **быстрый обзор (index.html)**. Это настоящий статический HTML, загружается без Python, маримо или CDN, с графиками, формулами, раскрывающимся кодом из настоящего Colab и итоговым выводом.

**Это преднамеренное изменение поведения главной ссылки:** ранее marimo открывался сразу по корневому адресу, теперь там надёжная главная с кнопкой «Запустить интерактивный marimo». Это существенно повышает доступность отчёта при слабом интернете, но сам marimo всё ещё зависит от внешних Python-пакетов.

## Безопасное обновление

**Ничего автоматически не изменено в GitHub.** Перед выкладкой сохранить копию действующего репозитория/ветку. Для GitHub Pages обновить `photo_app.py`, оба CSS, index.html, landing.css, report-assets, backup-report, public и workflow **одним коммитом** — иначе временно могут сломаться ссылки. Не трогать общий `ekairaliev/AppStat-Lab01`.

В ветке проверить GitHub Actions, затем домашнюю, /interactive/, /colorlab_report.html. После объединения — инкогнито + другой браузер/сеть, все четыре интерактивных сценария. В среде GitHub Actions ошибка сборки возможна; до успешной сборки не считать новую версию проверенной.

## Ограничения

- Главная с графиками **не требует ни Python, ни интернета для библиотек**; но нужна доступность GitHub Pages.
- В интерактивной части Pyodide и Python-пакеты по-прежнему загружаются из внешних источников — ошибка `Failed to fetch` в отдельных сетях **возможна**. Если это критично, следующий отдельный этап — попробовать `--offline` export по документации marimo (нужен Playwright Chromium в GitHub Actions).
- Важные расчёты в ноутбуке — статистика пары HSV для 10k тестовых изображений CIFAR-10. На сайте *не* заявляется исследование трёх случайных величин (дополнительный дизайнерский проект — отдельный).

## Предварительная локальная проверка

Из папки проекта запустить `python -m http.server 8000`, открыть `http://localhost:8000/index.html`. Это проверяет статическую страницу, но **не** развёрнутый интерактивный WASM, который нужно экспортировать через marimo.

## Локальная проверка кнопки «Интерактивная лаборатория»

В архиве `interactive/index.html` является **локальной информационной страницей**, а не самой WebAssembly-лабораторией. Она устраняет 404 при проверке дизайна через `python -m http.server 8000`, но не запускает Python-эксперименты.

Чтобы построить настоящий интерактивный сайт локально, установите Python-пакеты `marimo`, `uv`, `numpy`, `pandas`, `matplotlib`, `scipy`, `plotly`, `pillow`, затем из папки проекта выполните:

```cmd
python -m marimo export html-wasm photo_app.py -o interactive --mode run --no-show-code
python -m http.server 8000
```

После экспорта `/interactive/` должен открывать marimo, а не информационную страницу. Возможны дополнительные зависимости, проверяйте вывод команды экспорта. При публикации через `.github/workflows/pages.yml` экспорт выполняется автоматически, и информационная страница в сборку не копируется.


## Формулы на главной странице
Все 6 формульных блоков `index.html` преобразованы из линейного текста в нативную математическую разметку MathML. Дроби, индексы, пределы сумм и квадратные корни отображаются в математическом виде даже при локальном просмотре без интернета. Библиотеки MathJax/KaTeX не требуются. Проверено: наличие 7 формул MathML (в 6 блоках), отсутствие старых строковых формул. Для просмотра распакуйте ZIP и запустите `python -m http.server 8000`. Публикация на GitHub не выполнена.


## Исправление математических формул
Все формулы главной страницы теперь представлены точными локальными SVG, созданными из математической записи. Это устраняет ошибки отображения MathML в некоторых браузерах. Формулы сохраняют масштабирование в пределах карточек, не требуют интернета и не затрагивают код, графики или расчёты.
